## 1. 목적과 범위

STAGE.ONE A탭에서 익명 팬이 자연어로 묻고, 에이전트가 아티스트·공연 데이터를 조회해 답하며, 화면 이동(UI 액션)을 데이터로 돌려준다.

| 구분 | 내용 |
| --- | --- |
| 이 저장소 | 에이전트 API 전용 (Python, FastAPI, OpenAI Agents SDK). Cloud Run 배포 |
| on-stage 저장소 | A탭 프런트, 3D 궤도, 액션 실행, 패널 UI, ko/en 고정 문구 사전 |
| 1차 MVP | 한·영 Q&A + 카메라 이동(3D 포함) |
| 제외 | 로그인, 쓰기 도구(예매·결제), 대화 저장, 음성 |
| 우선순위 | 범위 작게, 비용 작게. 포트폴리오·이력서 용도 |

## 3. 아키텍처

```
브라우저(A탭, on-stage)
  │  POST /guide/stream  { requestId, sessionId, locale, message, context? }
  │  ← SSE: tool_status | text_delta | action | retract | error | done
  ▼
FastAPI (Cloud Run, 인스턴스 1대)
  ├─ L0 입력 길이 한도 (세션 턴 한도는 4단계에서 추가)
  ├─ L1 IP·일일 전체 한도
  ├─ L2 규칙 필터 (fast-block / fast-pass)
  ├─ L3 소형 분류기 (애매한 것만, run_in_parallel=False)
  ├─ L4 메인 에이전트 + 읽기 도구 3개
  └─ 출력 검사 (MVP: 답변의 도시 코드/이름이 도구 결과에 있는지만)
        │ httpx (5분 TTL 캐시, 실패 시 stale)
        ▼
  on-stage  GET /api/artists  (현재 인증 없음)
```

모듈 경계 (파일은 구현 계획에서 확정):

| 모듈 | 책임 | 의존 |
| --- | --- | --- |
| `data` | `/api/artists` 호출·캐시, slug/city enum 생성 | httpx |
| `tools` | `listArtists`, `getArtist`, `searchShows` (읽기 전용, 날짜 계산 포함) | `data` |
| `guard` | L0~L3 입력 방어, 출력 검사 | `data`(enum) |
| `limits` | IP·일일 전체 카운터, 세션 TTL 히스토리 | 없음 |
| `agent` | Agents SDK 에이전트, 동적 지시문(locale), 액션 수집 | `tools`, `guard` |
| `api` | FastAPI 라우트, SSE 직렬화, CORS, 취소 처리 | 전부 |
| `contracts/` | on-stage 계약 사본, 요청·이벤트·액션 모델(Pydantic), 골든 fixture. §8.1 | 없음 |

## 4. API 계약

### 요청 `POST /guide/stream`

| 필드 | 설명 |
| --- | --- |
| `requestId` | 클라이언트 UUID. 형식은 `^[A-Za-z0-9_-]{1,64}$` (로그 주입 방지). 로그 상관관계용 id일 뿐 서버는 멱등 처리를 하지 않는다. "다시 시도"는 새 요청이다 (§7.2) |
| `sessionId` | 브라우저 `sessionStorage` UUID. 형식은 `^[A-Za-z0-9_-]{1,64}$`. 서버는 신뢰하지 않음 (회전 가능) |
| `locale` | `ko` / `en`. 기본 응답 언어. 사용자가 다른 언어로 물으면 그 언어로 답함 |
| `message` | 사용자 질문 (길이 상한 적용) |
| `context` | 선택. 현재 페이지(`{ view: "orbit" | "tour", slug?, section? }`)를 동적 지시문에 주입. `section`(`hero`/`tour`/`album`/`gallery`)은 `view="tour"`일 때만 의미가 있고, 모르는 값은 요청을 거절하지 않고 무시한다 |

### SSE 이벤트

| 이벤트 | 페이로드 | 목업 대응 |
| --- | --- | --- |
| `tool_status` | `{ tool, key }` (`key`는 사전 키, 문구는 프런트가 ko/en으로 표시) | "공연 일정을 확인했어요" |
| `text_delta` | `{ text }` | 스트리밍 답변 |
| `action` | `{ type, ...payload }` (답변 끝에 한 번. **`retract`된 턴에서는 보내지 않는다**) | "궤도 카메라가 AURORA로 이동했어요" |
| `retract` | `{ reason }` (출력 검사 실패 시 프런트가 말풍선을 고정 문구로 교체. MVP의 `reason`은 `unverified` 하나. §6.2) | "확인되지 않은 정보는 답하지 않아요" |
| `error` | `{ code }` (`rate_limited`, `off_topic`, `too_long`, `busy`(4단계), `session_limit`(4단계, 제안 §7.3), `upstream`, `internal`) | 한도·오류 상태 |
| `done` | `{}` | 입력창 복귀 |

스트림 순서는 정상 `text_delta… → action? → done`, 출력 검사 실패 `text_delta… → retract → done`(action 없음), 오류 `error`(종료, `done` 없음)다. `retract` 뒤에도 입력창이 돌아오도록 `done`을 보낸다.

`off_topic`, `rate_limited` 같은 안내 문구는 LLM이 만들지 않고 프런트 사전이 `code`로 표시한다. 클라이언트가 연결을 끊으면(답변 멈추기) 서버는 에이전트 실행을 취소한다. 같은 `sessionId`에 진행 중인 요청이 있으면 새 요청은 `busy`로 거절한다 (히스토리 순서 보호). `busy`는 세션 상태가 생기는 **4단계에서 도입**한다. 진행 중 표시는 정상 종료뿐 아니라 취소·연결 끊김·오류 시에도 반드시 `finally`에서 해제한다. 해제되지 않으면 그 세션이 영구히 `busy`가 되기 때문이다.

입력 길이는 두 겹으로 제한한다. 200자 초과(L0)는 HTTP 200 + SSE `error` `too_long`으로 알려 프런트가 안내 문구를 보여 주게 하고, 2000자 초과는 데이터 모델 검증에서 HTTP 422로 거절한다(본문 폭주 방어). 2000자 초과는 정상 사용자 입력으로 보지 않으므로 프런트는 입력창에서 길이를 제한하고, 422는 일반 오류로 처리한다.

전송 방식: 요청이 POST 본문을 가지므로 클라이언트는 **`fetch` 스트리밍(`ReadableStream`)** 으로 SSE를 읽는다. `EventSource`는 GET만 지원해서 쓸 수 없다.

### UI 액션

| 액션 | 페이로드 |
| --- | --- |
| `focusArtist` | `{ slug }` |
| `openTour` | `{ slug, section? }` |
| `highlightCity` | `{ slug, city }` (`city`는 `cities[].code`, 예: `TYO`, `LA`). 4단계에서 도입. 서버 검증·호출 규칙은 §7.3 |

`slug`·`city`는 서버가 `/api/artists`에서 만든 enum으로 검증하고, 프런트도 실행 전에 다시 검증한다. 모르는 액션은 무시하고 답변은 항상 표시한다.

2b단계에서 에이전트는 `focusArtist`, `openTour`만 보내고 `openTour`는 `section`을 생략한다(생략하면 on-stage는 `tour`로 본다). 섹션 값 `hero`/`tour`/`album`/`gallery`는 on-stage가 정했고 요청 `context.section`과 `openTour.section`에 같은 값을 쓴다. 서버는 `view=tour`이고 `slug`가 같으며 현재 `section`이 `tour`이거나 없을 때만 `openTour`를 거른다. 의미와 on-stage가 할 일은 `contracts/ui_actions.md`에 있다. 아티스트 페이지 섹션 구분과 `context.section` 전송, `openTour`의 같은 페이지 스크롤은 on-stage 작업이며 §14.3에 인수인계 항목으로 기록했다.

## 5. 도구와 데이터

`/api/artists` 한 응답에서 모든 도구를 만든다. 사용 가능한 필드: `slug, name, nameKo, tour, stats, cities[code,name,date], tracks, news`.

| 도구 | 입력 | 반환 |
| --- | --- | --- |
| `listArtists` | 없음 | slug, name, nameKo, 투어명, 다음 공연 요약 |
| `getArtist` | `slug` (enum) | 투어·도시 목록(날짜, 남은 일수)·트랙 |
| `searchShows` | `city?`, `month?`, `artist?`, `upcomingOnly?` | 조건에 맞는 공연 목록 |

- 날짜 계산(D-n, "곧")은 도구가 서버 시각(KST)으로 계산해 `daysUntil`로 반환한다. LLM이 날짜를 계산하지 않는다.
- 도구 입력·액션은 코드(`slug`, 도시 `code`)만 쓴다. "도쿄"/"Tokyo" → `TYO`는 에이전트가 변환한다.
- 도구 결과는 히스토리에 저장하지 않는다 (§7).
- **도시 수·목록 규칙 (확정)**: on-stage 코드(`src/lib/data.ts`) 기준으로 `stats.cities`는 `shows` 테이블 전체 행 수이고, `cities[]`는 그중 `featured = true`인 공연(A탭 투어 오빗 노출 대상)만 담은 목록이다. 도구는 `totalCities`(= `stats.cities`)와 `featuredCities`(= `cities[]`)를 구분해 반환한다.
  - 도시 "수"를 답할 때는 `totalCities`를 쓴다 (예: aurora 26).
  - **곡 수·목록도 같은 규칙**이다: `stats.tracks`는 `tracks[]` 길이와 다를 수 있어(실제 응답 aurora 8 vs 4) 도구는 `totalTracks`(= `stats.tracks`)와 `featuredTracks`(= `tracks[]`)를 구분해 반환한다. "몇 곡"은 `totalTracks`로 답하고 곡 목록은 "대표 곡"이라고 밝힌다.
  - 도시 "목록"은 `featuredCities`만 알고 있으므로 "대표 도시"라고 밝혀서 답하고, 전체 목록인 것처럼 말하지 않는다.
  - `searchShows`는 현재 `featuredCities`만 검색할 수 있다. 결과가 없어도 "등록된 일정에서 찾지 못했다"고만 답하고 "공연이 없다"고 단정하지 않는다.
  - 전체 공연(`shows` 테이블, 도시·국가·공연장·날짜·수용 인원)은 DB에 있으나 현재 GET API로 노출되지 않는다. **on-stage에 읽기 엔드포인트를 추가하기로 확정**했고(§12 #11), 추가되면 `searchShows`·`getArtist`는 `featured` 여부와 무관하게 전체 공연을 검색하고 "대표 도시" 단서 문구는 필요 없어진다.
  - 전환을 쉽게 하려고 `data` 모듈은 공연 목록을 한 함수(예: `load_shows(slug)`)로만 내놓고, 도구는 이 함수만 호출한다. 현재 구현은 `cities[]`에서, 엔드포인트가 생기면 새 응답에서 채운다.
  - 전환 후 "도시 수"는 목록에서 `city_code` 중복을 제거해 계산할지, `stats.cities`(공연 행 수)를 쓸지를 계약 갱신 시 정한다. 같은 도시의 다른 날짜 공연이 있으면 두 값이 달라진다.

## 6. 가드레일과 토큰 비용

| 계층 | 처리 | 토큰 |
| --- | --- | --- |
| L0 | 입력 길이 상한(초기 200자). 세션 턴 상한(초기 20턴)은 세션 히스토리와 함께 4단계에서 추가 | 0 |
| L1 | IP별 분당·일일 한도, 전체 일일 한도(킬스위치). 카운터는 서버 메모리라 재시작 시 초기화되는 best-effort | 0 |
| L2 fast-block | 명백한 인젝션 패턴(시스템 프롬프트 노출, 역할 변경 등), 한·영 모두. **fast-pass보다 항상 먼저 검사한다** (아티스트명이 있어도 차단) | 0 |
| L2 fast-pass | 아티스트명·도시명·투어 키워드가 있으면 분류기 생략. 영어는 단어 경계 매칭 (§6.3) | 0 |
| L3 | 소형 모델 분류기. L2가 AMBIGUOUS로 판정한 요청만. `run_in_parallel=False`로 판정이 끝난 뒤 메인 실행. 차단 시 메인 토큰 0. 기준·문구는 §6.1 | 소량 |
| L4 | 메인 에이전트. 시스템 프롬프트에도 주제 이탈 거절을 명시 (최종 방어선) | 본 호출 |
| 출력 (MVP) | 답변에 등장한 도시 코드/이름이 해당 턴 도구 결과(또는 사용자 질문)에 있는지만 규칙 대조. 실패 시 `retract`하고 action은 보내지 않는다. 날짜 대조는 MVP 제외 (날짜는 도구가 계산해 반환하므로 LLM이 만들 여지가 작음). 상세 §6.2 | 0 |
| 월 한도 | **선불 크레딧 잔액이 상한이다 (auto-reload OFF 확정).** 잔액이 소진되면 API가 요청을 거절한다. 코드 없음. 잔액은 다른 에이전트와 공유하므로 투어 가이드 전용 프로젝트·키를 따로 발급한다 (§12 #9) | - |

알려진 한계 (문서화 대상):

- 토큰 없이 막을 수 있는 건 길이·한도·명백한 인젝션까지다. 주제 이탈은 키워드 블록리스트로 막을 수 없고, 허용 목록은 이어지는 질문("그다음엔?")을 오탐한다. 그래서 애매한 것은 분류기로 보낸다.
- 아티스트명을 섞은 이탈 질문("AURORA 말고 점심 추천해줘")은 fast-pass를 통과한다. 메인 프롬프트의 거절, 길이·일일 한도로 피해를 제한한다.
- 분류기 오류·타임아웃은 fail-closed(차단, `off_topic` 아닌 `upstream` 코드)로 처리한다.
- 세션 id는 회전 가능하므로 비용 방어선은 IP·전체 일일 한도다.
- 일일 한도 카운터는 서버 메모리에 있어서 인스턴스 재시작·스케일 투 제로 시 초기화된다. 정확한 한도가 아니라 best-effort 방어이고, 최종 상한은 선불 크레딧 잔액(auto-reload OFF)이 맡는다.
- 잔액은 다른 에이전트와 공유한다. 별도 프로젝트·키는 사용량 분리와 폐기(revoke)를 쉽게 할 뿐이고 지출 상한을 따로 만들어 주지는 않는다. 따라서 이 에이전트가 공유 잔액을 소진하지 않도록 앱 내 L1 한도를 보수적으로 둔다.
- 잔액 소진 시 OpenAI 호출이 오류를 반환한다. 이 오류는 `upstream`으로 안내하고 테스트로 고정한다 (§13 3단계).
- 출력 검사 범위는 도시 코드/이름 대조뿐이다. 도시 이름은 현재 한국어(`cities[].name`)라 영어 답변의 영문 도시명은 별칭 표 없이는 대조할 수 없다 (§12 #10). 날짜·트랙명·투어명 대조는 MVP 범위 밖이다.
- input guardrail은 체인의 첫 에이전트에만 적용된다. 핸드오프를 도입하면 재검토한다 (MVP는 단일 에이전트).
- `run_streamed`의 블로킹 입력 가드레일: SDK 0.23.1 소스(`run_internal/run_loop.py`)에서 `run_in_parallel=False` 가드레일이 첫 모델 호출 전에 끝나고, 차단되면 `stream_events()` 도중 `InputGuardrailTripwireTriggered`가 발생함을 읽어서 확인했다. 실제 호출로 메인 토큰 0은 구현 시 테스트로 고정한다 (§6.1). 이 예외는 `stream_guide`가 잡아 `off_topic`으로 보낸다. 잡지 않으면 `api`의 catch-all이 `upstream`으로 보낸다.
- 출력 검사는 사전에 없는 도시(예: 목록에 없는 "파리")를 지어내면 잡지 못한다.
- 영어 단어와 겹치는 아티스트 이름("aurora borealis")은 fast-pass를 통과한다. 메인 프롬프트의 거절이 막는다.
- 초기 한도 수치는 구현 시 조정하는 시작값이다.

### 6.1 L3 분류기 (3단계)

| 항목 | 결정 |
| --- | --- |
| 호출 대상 | L2가 AMBIGUOUS로 판정한 요청만. `api`가 L2 판정을 `GuideContext`의 플래그로 넘기고, 가드레일은 플래그가 꺼져 있으면 LLM 호출 없이 통과시킨다 |
| 모델 | **`gpt-4.1-mini`(메인과 같은 모델)로 확정.** `CLASSIFIER_MODEL` 환경 변수로 교체 가능. nano 제외 (§12 #4). 측정 결과(2026-10-15, 같은 §6.5 세트, 단독 호출 15회 지연): `gpt-4.1-mini` 중앙값 0.84초·최대 1.13초·오류 0, `gpt-5.6-luna` 1.25초·2.42초·0(동시 호출 테스트에서 타임아웃으로 두 번 모두 한 그룹씩 실패, 재현 불안정), `gpt-6-luna` 2.19초·4.00초·타임아웃 2건. 더 싼 모델의 이득은 차단 건당 약 0.0001달러(하루 상한 1000건 기준 약 0.1달러)로 작고 지연이 늘어 채택하지 않았다. temperature 등 파라미터 지원은 모델을 바꿀 때 문서로 확인하고 미지원이면 값을 비운다 |
| 설정 | temperature 0, 구조화 출력 `{verdict: allow\|block, category: off_topic\|injection\|abuse}`, 타임아웃 4초, 재시도 없음 |
| 실패 | fail-closed. 오류·타임아웃은 `upstream`. 잔액 소진 오류도 같다 |
| 차단 처리 | `stream_guide`가 `InputGuardrailTripwireTriggered`를 잡아 `error: off_topic` 한 건만 보낸다 (`done` 없음). 새 이벤트·코드 없음 |
| 로그 | 분류기 토큰·지연·`category`만 남긴다. 질문 본문은 남기지 않는다. 분류기 토큰은 메인 `usage`와 별도로 기록한다 |

목적: L3는 모델을 싸게 쓰려는 장치가 아니라, 주제 이탈·인젝션·남용 요청에서 도구와 긴 지시문이 달린 메인 실행을 시작하지 않게 하는 문 앞의 검문이다. 같은 모델이어도 한 번의 짧은 판정이라 차단 건당 비용이 메인의 약 8분의 1~10분의 1이다 (실측 메인 입력 1458~3116토큰, 분류기 지시문 434자 + 질문). 판정은 프롬프트의 기대가 아니라 코드(tripwire)가 강제하고, 분류기는 도구·action이 없고 출력이 두 값뿐이라 속아도 잃는 것이 적다.

판정 원칙: **의심스러우면 통과**. 오탐(정상 질문 차단)의 피해가 미탐(메인 한 번 더 호출)보다 크고, 메인 프롬프트의 거절·L1 한도·선불 잔액이 뒤를 받친다. 분류기는 단일 메시지만 본다(세션 히스토리는 4단계). 맥락 없는 짧은 후속 질문은 통과로 본다.

| 차단 | 통과 |
| --- | --- |
| 투어·공연과 무관한 주제 (음식, 날씨, 코딩, 일반 상식, 번역·글쓰기 대행) | 아티스트·공연·도시·날짜·티켓·트랙·소식 질문 (한·영·기타 언어) |
| 시스템 프롬프트 노출·역할 변경 (L2가 놓친 변형) | 맥락 없는 짧은 후속 질문 ("그다음엔?", "거긴 언제야?") |
| 비용 소모성: 긴 글·반복 출력·목록 나열 대행 ("1000번 써줘", "에세이로 써줘") | 인사·감사·"뭘 할 수 있어?" 등 가이드 자체에 대한 질문 |
| | 목록에 없는 아티스트 질문 (메인이 "찾지 못했다"고 답한다) |

오분류 시 사용자 문구는 프런트 사전이 `off_topic`으로 표시한다 (사유 구분 없음. 공격자에게 정보를 주지 않는다):

- ko: "이 질문은 제가 도와드리기 어려워요. 아티스트, 공연, 투어 일정에 관해 다시 물어봐 주세요. 예: '서울에서 곧 공연하는 팀은?'"
- en: "I can't help with that one. Try asking about artists, shows, or tour dates, e.g. 'Who's playing in Seoul soon?'"

### 6.2 출력 확인과 retract (3단계)

- 검사 시점: 스트리밍을 유지하고 **답변이 끝난 뒤** 검사한다. 버퍼링하면 스트리밍 체감이 사라진다. 그래서 실패 시 말풍선 교체(`retract`)가 필요하다.
- 허용 집합: 이번 턴 도구 결과의 도시 코드 ∪ **사용자 질문에 나온 도시**. 사용자가 물은 도시를 답변이 되풀이하는 것("파리 일정은 찾지 못했어요")은 정상이므로 막지 않는다.
- 문제 판정: 답변에 나온 알려진 도시(코드·한글 이름·영문 별칭)가 허용 집합에 없으면 `retract`.
- 매칭: 코드는 대문자 단어 경계, 영문 별칭은 대소문자 무시 단어 경계, 한글 이름은 부분 문자열. 영문 별칭은 `guard`의 코드→영문명 표로 둔다 (§12 #10).
- 도구 결과 수집: 도구 코드는 건드리지 않고 `stream_guide`가 SDK의 `tool_output` 이벤트를 파싱한다.
- 순서: 검사 통과 시 `text_delta… → action? → done`, 실패 시 `text_delta… → retract(unverified) → done`. **`retract`된 턴은 action을 보내지 않는다.** action은 답변이 끝난 뒤에만 나가므로 되돌릴 실행은 없다. `error`는 종료 이벤트라 쓰지 않는다.
- 히스토리: `retract`된 턴은 4단계 세션 기록에 저장하지 않는다 (§7).
- 로그: `retract` 발생 횟수와 사유만 남긴다.

### 6.3 L2 단어 경계 (3단계)

- 순서는 항상 **fast-block → fast-pass → AMBIGUOUS**. 아티스트명이 들어 있어도 인젝션 패턴이 있으면 BLOCK이다. 현재 `classify`가 이미 이 순서이고, 3단계에서 회귀 테스트로 고정한다.
- 영어(ASCII) 토큰은 단어 경계로 매칭하고 복수·소유격(`s`, `'s`)을 허용한다. `shows`, `AURORA's`는 통과하고 `innovation`(nova), `detour`(tour)는 걸리지 않는다.
- 한국어는 조사가 붙으므로("서울에서") 부분 문자열을 유지한다. 오탐을 부르는 키워드 **"도시"는 삭제**한다 ("도시락"). 도시명은 어휘집이 이미 잡는다.

### 6.4 액션 판단 안정화 (3단계)

문제: (a) orbit에서 "AURORA 투어 일정 보여줘"가 OpenTour/FocusArtist로 흔들림 (b) "오로라", "aurora"처럼 한글·소문자 이름만 말하면 FocusArtist가 잘 안 나감. 원인 추정: 프롬프트가 "focusArtist를 호출해도 된다"(선택형)와 "투어 일정 보여줘는 openTour"를 동시에 말하고, "오로라/aurora"가 자연현상 단어로 읽힌다. 측정으로 확인한다.

| 순서 | 방법 | 내용 |
| --- | --- | --- |
| ① | 프롬프트 보정 | 아티스트 표에 표기 변형(AURORA·오로라·aurora)을 slug와 함께 넣고 "자연현상이 아니라 이 아티스트"를 명시. 액션 규칙은 선택형이 아닌 **의도→액션 결정표 + 예시 문장**으로 다시 쓴다 |
| ② | 설정 | 메인 `temperature=0.2` (`OPENAI_TEMPERATURE`, 비우면 미설정). 현재 `gpt-4.1-mini`는 추론 모델이 아니라 추론 강도 설정이 없다. 모델을 바꿀 때는 파라미터 지원을 문서로 확인한다 |
| ③ | 서버 힌트 | ①②로 부족할 때만. 아티스트 이름 + 이동 동사 규칙으로 의도를 판단해 동적 지시문 **끝**에 힌트 한 줄을 붙인다 (프롬프트 캐시 보호). 모델이 최종 결정한다 |

측정: orbit 화면에서 같은 문장을 8회씩 실행해 기대 액션 횟수를 센다. 통과는 8회 중 6회 이상, 목표는 7회다. ③은 4문장 중 하나라도 6회 미만일 때만 진행한다.

| 문장 | 기대 액션 |
| --- | --- |
| "AURORA 투어 일정 보여줘" | `openTour(aurora)` |
| "오로라 투어 보여줘" | `openTour(aurora)` |
| "오로라 알려줘" | `focusArtist(aurora)` |
| "aurora 알려줘" | `focusArtist(aurora)` |
| 대조군 "서울에서 누가 공연해?" | 액션 없음 (8회 중 7회 이상) |

측정 결과(2026-10-15, `gpt-4.1-mini`, orbit, 8회씩, 프롬프트 보정 ①②만 적용, 서버 힌트 ③ 불필요): "AURORA 투어 일정 보여줘" `openTour` 8/8, "오로라 투어 보여줘" `openTour` 8/8, "오로라 알려줘" `focusArtist` 8/8, "aurora 알려줘" `focusArtist` 8/8, 대조군 "서울에서 누가 공연해?" 액션 없음 8/8. 한 번의 측정이므로 모델·프롬프트를 바꾸면 `scripts/measure_actions.py`로 다시 잰다.

### 6.5 테스트 세트 (3단계)

| 층 | 방법 | 기준 |
| --- | --- | --- |
| 규칙 (L2, 출력 검사, 이벤트 순서) | LLM 없는 단위 테스트 | 100% |
| 메인 호출 0 | 메인 모델을 가짜로 바꿔 차단 시 호출 횟수 확인 | 결정적 |
| 분류기 | `llm` 마커, 질문마다 3회. **L2를 거치지 않고 분류기 함수를 직접 호출한다** (L2가 fast-pass하는 문장은 실서비스에서 L3까지 가지 않으므로) | 케이스별 2/3 이상, 세트 전체 90% 이상 |
| L2 통과 이탈 문장 ("AURORA 말고 점심 추천해줘", "Tell me about aurora borealis") | `llm` 마커, 3회. `classify`가 PASS임을 먼저 단언하고 메인 에이전트의 거절(도구·action 없음, 투어 질문 권유)을 확인 | 케이스별 2/3 이상 |
| 액션 | `llm` 마커, 문장마다 8회 (§6.4) | 8회 중 6회 이상 |

질문 구성(한·영 반반): 통과 약 12개 (투어·도시·날짜·티켓·트랙 질문), 차단 약 12개 (주제 이탈, 인젝션 변형, 비용 소모), 경계 약 8개 (이어지는 질문, 영어, 목록에 없는 아티스트). 실제 문장 목록은 구현 계획에 둔다.

## 7. 세션과 히스토리 비용

- 저장소: 서버 메모리 dict, `sessionId` → 최근 6턴(12메시지), 30분 TTL. DB·Neon 사용 안 함.
- 개수 상한: 세션 dict는 최대 500개(초기값)로 두고 초과 시 가장 오래 쓰지 않은 세션부터 제거한다 (LRU). 세션 id를 회전시키는 요청으로 메모리가 늘어나는 것을 막는다.
- 텍스트만 저장: 사용자 질문과 최종 답변만 남기고 도구 호출·결과는 제외.
- 턴 커밋: 한 턴은 `done`으로 정상 종료됐을 때만 히스토리에 커밋한다. 실패·취소·차단된 요청은 쌓이지 않는다.
- `retract`된 턴은 히스토리에 커밋하지 않는다. 검증에 실패한 답변이 다음 턴의 맥락으로 들어가 잘못된 도시를 되풀이하는 것을 막기 위해서다. (대안: 고정 문구로 치환해 커밋하는 방식이 있으나, 맥락 연속성보다 단순함을 우선해 채택하지 않는다.)
- 프롬프트 캐싱: 시스템 프롬프트·도구 정의를 앞에 고정하고, `locale`·`context` 같은 동적 값은 뒤에 붙인다.
- 인스턴스 재시작·유휴 종료 시 히스토리는 사라진다. "대화는 저장하지 않음" 원칙과 일치하므로 허용한다.

### 7.1 트레이싱과 "대화 미저장" 원칙

**결정: 운영 환경에서는 SDK 트레이싱을 끈다.**

- Agents SDK 트레이싱은 기본이 켜져 있고, 켜져 있으면 실행 기록(LLM 입출력, 도구 호출 인자·결과)이 OpenAI 트레이스 서버로 전송된다. 이는 "대화는 저장하지 않음"과 충돌한다.
- 운영에서는 환경 변수 또는 코드(`set_tracing_disabled(True)`)로 끈다. 정확한 설정 이름은 구현 시 SDK 문서로 확인한다.
- 로컬 개발과 가드레일 스파이크에서만 켠다. 켤 때도 민감 데이터 포함은 끄고(`trace_include_sensitive_data=False`) 실제 사용자 입력이 아닌 테스트 질문만 쓴다.
- 비용·지연·차단 계층 측정은 자체 로그로 한다: 토큰 수, 지연, 차단된 계층 코드, `requestId`. 질문·답변 본문은 로그에 남기지 않는다.
- 한계: 트레이싱을 꺼도 OpenAI API 자체의 표준 데이터 보존 정책은 별개로 적용될 수 있다. 따라서 "저장하지 않는다"는 "이 서비스는 대화를 저장하지 않는다"는 뜻으로 한정하고, UI 문구(목업: "대화는 저장되지 않아요")를 이 의미에 맞는지 검토한다 (§12 #8).

### 7.2 `requestId`와 재시도

| 안 | 동작 | 장점 | 단점 |
| --- | --- | --- | --- |
| A. 멱등 처리 | 같은 `requestId`면 완료된 응답 이벤트를 재생하고, 진행 중이면 합류 | 재시도 중복 과금 0, 중복 턴 없음 | 이벤트 버퍼를 서버 메모리에 보관해야 해서 상태가 늘고, 인스턴스 1대·재시작 시 소실. "대화 미저장" 원칙과도 어긋남. 구현·테스트 범위 증가 |
| **B. 다시 시도 = 새 요청 (MVP 채택)** | `requestId`는 로그용. 재시도는 새 요청으로 처리 | 서버 상태 없음, 구현 단순 | 재시도마다 토큰 과금. 방어는 IP·일일 한도가 맡음 |

B를 채택하는 근거: 중복 턴은 "`done` 정상 종료 시에만 히스토리 커밋" 규칙으로 막히고, 같은 세션의 동시 요청은 4단계부터 `busy`로 막힌다. 남는 비용은 재시도 과금뿐이고 이는 한도로 제한된다. 필요해지면 A로 올린다.

### 7.3 4단계 설계

요청 처리 순서 (`api`의 `events()`):

```
L0 길이 → L1 IP 한도 → 데이터 → 세션 턴 상한 → L2 규칙 → busy 획득
  → 에이전트 실행(히스토리 포함) → done이면 커밋 → finally에서 busy 해제
```

| 항목 | 제안 |
| --- | --- |
| 저장소 | `limits.py`에 `SessionStore`를 둔다 (§3 표대로). `OrderedDict`를 마지막 사용 순으로 유지한다. 만료·초과는 오래된 쪽(앞)부터 제거하고 진행 중인 세션은 건너뛴다. 이벤트 루프가 하나라 "확인 → 표시" 사이에 `await`만 없으면 락이 필요 없다 |
| 세션 값 | `history`(최근 6턴, 텍스트만), `committed_turns`(커밋된 턴 수), `in_flight_since`(진행 중 표시 시각) |
| 커밋 | `api`가 `text_delta`를 모으고 `retract`가 있었는지 본다. `done`을 받았고 `retract`가 없었을 때만 (질문, 답변)을 커밋한다. **`done`을 클라이언트에 내보내기 전에** 커밋해서, 마지막 순간에 연결이 끊겨도 정상 턴이 사라지지 않게 한다. `error`(L3 차단 포함)·취소·연결 끊김·`retract`는 커밋하지 않는다 |
| 히스토리 주입 | Runner 입력을 `[이전 메시지…, 현재 질문]` 목록으로 보낸다. 지시문은 그대로 두어(동적 값이 뒤) 앞부분 캐시를 유지한다. **구현 첫 작업으로 SDK가 assistant 텍스트 메시지와 목록 입력의 입력 가드레일을 의도대로 처리하는지 스파이크로 확인한다** |
| L2·L3 | L2는 현재 메시지만 본다. L3 분류기는 현재 메시지와 **직전 사용자 질문 하나**를 받는다(전체 히스토리 아님. 비용·주입 면적을 줄이고, "그다음엔?" 같은 후속 질문을 덜 오탐한다). 지금 `l3_classifier`는 목록 입력이 오면 통째로 직렬화하므로 수정이 필요하다 |
| 출력 검사 | 허용 도시 = 도구 결과 ∪ 현재 질문 ∪ **히스토리(커밋된 질문·답변)의 도시**. 커밋된 답변은 이미 검사를 통과한 것이라 믿어도 되고, 빼면 "거기 몇 시야?"처럼 도구 없이 되묻는 답이 오탐으로 `retract`된다 |
| 턴 상한 | 커밋된 턴이 20 이상이면 새 요청을 `session_limit`으로 거절한다 (제안: **새 코드 값**, 새 이벤트 타입은 아님). 대안은 `rate_limited` 재사용인데, 사용자에게 "새 대화를 시작하라"고 안내하지 못한다 |
| busy | 같은 세션에 진행 중 표시가 있으면 `busy`. 표시는 `events()`의 `finally`에서 해제한다. 안전망으로 120초가 지난 표시는 무시한다(해제 누락 버그가 있어도 세션이 영구히 막히지 않게) |
| 한도 순서 | IP 한도가 먼저다(모든 요청이 한도에 센다). `busy`는 L2 뒤, 실행 직전이다. L2 차단·L3 차단 요청은 턴 수에 세지 않는다 |
| `highlightCity` | 도구 `highlightCity(slug, city)`. `slug`는 enum, `city`는 **그 아티스트의 `load_shows` 도시 코드 안에** 있어야 한다(다른 아티스트의 도시는 기록하지 않고 오류를 돌려 스스로 고치게 한다). 한 답변에 액션 하나(기존 규칙). 호출 규칙(제안): 현재 화면이 `tour/<그 slug>`이고 특정 도시를 가리킬 때만. 그 밖에는 `openTour`·`focusArtist`. 순서는 `text_delta… → action → done`이고 `retract` 턴에서는 보내지 않는다. 화면 연출은 on-stage가 정한다 |
| KO\|EN | 빠진 곳은 없다(`locale` 요청 필드, 지시문, L2 영문 매칭, 출력 검사 영문 별칭, 분류기). 추가는 테스트만: 영어 후속 질문, 영어 `highlightCity` |
| 추천 칩 | 에이전트 쪽 변경은 없다. 칩 문구도 일반 요청이라 L2/L3를 통과해야 하고 IP 한도·20턴에 센다. on-stage에서 칩 문구 목록을 받아 회귀 테스트에 넣는다 |

알려진 한계:

- 인스턴스 재시작 시 히스토리와 진행 중 표시가 사라진다 (§7 허용 사항).
- "답변 멈추기" 직후 바로 새 요청을 보내면 해제가 끝나기 전이라 `busy`를 받을 수 있다. 프런트가 연결이 닫힌 뒤 보내도록 요청한다 (§14.6).
- 히스토리가 들어오면 출력 검사의 허용 도시가 넓어져, 이전 턴에 언급된 도시를 현재 도구 결과 없이 되풀이해도 통과한다. 도시만 대조하는 범위 안에서 허용한다.

## 9. 3D 궤도 (on-stage 쪽 작업의 계약)

- 2a단계에서 에이전트 없이 먼저 교체한다. 노드=구체, 궤도=선, 라벨=`drei <Html>`.
- 카메라 이동은 ref + `useFrame`으로 처리하고, React state는 이동 완료 시에만 커밋한다 (v2.2 Canvas 재구성 문제 회피).
- 기존 2D 컴포넌트는 삭제하지 않고 플래그로 복귀 가능하게 둔다.
- 완료 기준: 기존 hover·클릭 진입과 모바일 반응형 유지, 프레임 끊김 없음, `webglcontextlost` 0건.
- 액션이 `{ slug }` 데이터라 렌더러와 무관하므로, 3D가 지연되면 2D 회전으로 2b를 먼저 진행할 수 있다.

## 10. 배포

- Cloud Run, `max-instances=1`, 설정은 기존 FastAPI 에이전트와 동일하게 맞춘다 (구현 시 해당 설정을 확인해 복제).
- 인메모리 상태(세션, 카운터) 때문에 인스턴스는 1대여야 한다.
- 콜드 스타트가 데모에서 거슬리면 `min-instances=1`로 전환한다. 기획서의 B안(Next.js 내장 TS)은 폐기한다.
- SSE는 응답을 버퍼링하지 않도록 헤더와 서버 설정을 확인한다.
- `GET /health`: 외부 호출·LLM 호출 없는 가벼운 엔드포인트. 프런트가 패널을 열 때(또는 열기 버튼에 상호작용할 때) 한 번 호출해 콜드 스타트를 미리 깨운다. 사용자가 첫 질문을 보낼 때쯤 인스턴스가 준비돼 있게 하는 것이 목적이다. 페이지 로드 시점이 아니라 패널 열기 시점으로 두어 불필요한 기동을 줄인다. CORS 허용 목록은 `/guide/stream`과 동일하고, 느슨한 IP 한도를 따로 둔다.
- 시크릿(OpenAI 키)은 서버 환경 변수. 도구는 읽기 전용이고 on-stage 공개 API만 호출한다.
- 스택은 기존 에이전트와 맞춘다 (FastAPI, 배포 방식). Neon·DB는 이 에이전트에 도입하지 않는다.

## 14. on-stage 인수인계 대상 항목

이 저장소에서 on-stage를 수정하지 않는다. 아래는 나중에 on-stage 인수인계 문서(handoff)를 만들 때 그대로 옮겨 쓸 수 있도록 설계 단계에서 확인한 사실과 요구를 모아 둔 것이다. 다른 세션에서 인수인계 문서를 작성하면 이 절을 먼저 읽는다.

### 14.1 시드 데이터 불일치 (on-stage `/api/artists`)

확인 시점: 2026-10-13, `https://on-stage-nine.vercel.app/api/artists` 실제 응답. 에이전트는 이 데이터를 진실로 쓰므로 on-stage 시드에서 정리되면 에이전트 답변이 따라서 바뀐다.

| 아티스트 | `stats.cities` | `cities[]` 실제 개수 | 일치 | `news` 문자열 |
| --- | --- | --- | --- | --- |
| aurora | 26 | 4 (LA, LDN, SEO, TYO) | 불일치 | "AURORA 월드투어 서울 공연 D-3" |
| velvet | 8 | 4 (BUS, SEO, TPE, TYO) | 불일치 | "VELVET 단독 콘서트 티켓 오픈" |
| nova | 6 | 4 (BKK, HKG, SEO, SIN) | 불일치 | "NOVA 신보 'Bloom' 발매" |
| halo | 5 | 5 | 일치 | "HALO 팬미팅 'Ring' 개최 확정" |
| lumen | 5 | 4 (BUS, DGU, DJN, SEO) | 불일치 | "LUMEN OST 참여곡 공개" |
| echo | 2 | 2 | 일치 | "ECHO 데뷔 쇼케이스" |

관찰된 문제:

1. **`stats.cities`와 `cities[]` 개수가 4팀에서 다르다.** on-stage 코드로 원인이 확인됐다: `stats.cities`는 `shows` 전체 행 수(aurora 26), `cities[]`는 `featured = true`인 행만이다(aurora 4). 시드 오류가 아니라 의도된 필터다. 다만 필드 이름만으로는 이 구분이 드러나지 않고, `stats.cities`는 공연 행 수라서 같은 도시의 다른 날짜 공연이 있으면 도시 수보다 클 수 있다 (`shows`의 유니크 키가 `artist_id, city_code, show_date`). 기획서·목업의 "24개 도시"는 어느 쪽과도 맞지 않는다.
2. **`news`의 "D-3"이 날짜 데이터와 맞지 않는다.** aurora의 서울 공연은 `cities[]`에서 2026-12-15라서 2026-10-13 기준 D-3이 아니다. `news`는 고정 문자열이라 날짜가 지나도 갱신되지 않는다.
3. **지난 날짜가 `cities[]`에 남아 있다.** 예: aurora LA 2026-08-22. 에이전트는 `upcomingOnly`로 거르지만, "투어 도시 수"를 말할 때 지난 공연을 포함할지 기준이 시드에 없다.
4. 목업이 이 불일치를 그대로 반영한다: 대화 보드는 "4개 도시", 스트리밍 보드는 "24개 도시", 첫 화면 티커는 "서울 공연 D-3"이다.

처리 방침 (확정): 시드는 데모용 가짜 데이터이고 수정이 쉬우므로 이 저장소에서는 **기록만 하고** 별도 작업을 만들지 않는다. 두 값을 어떻게 통일할지는 on-stage 연결 시 해결한다.

에이전트 쪽 처리 (결정됨): 도시 **수**는 `stats.cities`를 쓰고, 도시 **목록**은 `cities[]`를 "대표 도시"로만 말한다 (§5). `news`의 날짜 표현은 답변 근거로 쓰지 않고, D-n은 도구가 `cities[].date`로 계산한다.

on-stage에 요청할 정리 (선택, 에이전트는 정리 전에도 동작):

- 통일 방식은 연결 시 결정한다. 후보: `cities[]`의 이름을 `featuredCities`처럼 "대표"가 드러나게 바꾸거나, `stats.cities`와 같은 길이가 되도록 전체 목록을 채운다. 어느 쪽이든 `contracts/artist_context.md`와 골든 fixture를 "계약 갱신"으로 갱신한다.
- `news`의 D-n 문구를 날짜에서 계산하거나 제거한다.
- 목업·기획서의 도시 수 문구를 시드에 맞춘다.

### 14.3-1 계약 재검증 요청 (on-stage에 인계할 때)

`contracts/artists.py`, `contracts/artist_context.md`, `contracts/fixtures/artists_response.json`은 on-stage 소스의 타입 정의를 읽고 만든 것이 아니라 **배포된 `GET /api/artists` 실제 응답(2026-10-13)** 에서 필드와 타입을 추론해 만들었다. `stats.cities`와 `cities[]`의 의미만 on-stage `src/lib/data.ts`를 근거로 했다. 그래서 on-stage 쪽에서 다음을 한 번 더 확인해 달라고 요청한다.

- `src/lib/types.ts`의 `Artist` 타입과 `contracts/artists.py`의 필드·타입이 일치하는지
- `null`이나 빈 값이 될 수 있는 필드가 있는지 (현재 모델은 `null`을 허용하지 않아, 어떤 아티스트에서 값이 비면 검증이 실패하고 에이전트는 `upstream`이 된다)
- `contracts/README.md`에 적은 출처 커밋(`e57361ae…`)이 배포본과 같은 버전인지
- 차이가 있으면 "계약 갱신" 태스크로 `contracts/`와 골든 fixture를 갱신한다

| H5 | `highlightCity` 액션 샘플을 on-stage 계약 테스트에 추가한다 (이 저장소 fixture `success_highlight_city`를 복사) | §8.1 |

### 14.4 참고 사실

- `/api/artists`는 현재 인증이 없고 CORS 헤더가 없다. 에이전트가 서버에서 호출하므로 영향이 없다.
