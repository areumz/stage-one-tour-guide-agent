# UI 액션 [요구사항]

이 파일은 **[요구사항]** 이다. 에이전트(이 저장소)가 보내는 `action` 이벤트의 의미와, on-stage 가 정하고 해야 할 일을 적는다.
페이로드 모양은 `guide_events.py`, 예시는 `fixtures/guide_events_sample.json` 이 기준이다. 설계 근거는 `docs/design.md` §4, §14.3.

## 요청 `context`

| 필드      | 값                                       | 설명                                                                                                           |
| --------- | ---------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `view`    | `orbit` \| `tour`                       | 현재 화면. 아티스트 페이지(`/artists/[slug]`)는 `tour`                                                         |
| `slug`    | 아티스트 slug (선택)                     | 현재 아티스트                                                                                                  |
| `section` | `hero` \| `tour` \| `album` \| `gallery` (선택) | 사용자가 보고 있는 섹션. **`view="tour"` 일 때만 의미가 있다.** 모르면 보내지 않는다 (에이전트는 "섹션을 모름"으로 본다) |

- 섹션 값 목록은 on-stage 가 정했다 (계약 갱신 C1, C2). 값을 늘리려면 "계약 갱신" 요청으로 전달한다. **모르는 값은 무시된다.** 요청을 거절하지 않고 `section` 이 없는 것으로 취급한다 (`view`, `slug` 는 지금처럼 엄격하다).

## 에이전트가 보내는 것

| 액션            | 페이로드                                                       | 단계                      |
| --------------- | -------------------------------------------------------------- | ------------------------- |
| `focusArtist`   | `{ slug }`                                                     | 2b (지금)                 |
| `openTour`      | `{ slug, section? }` (에이전트는 당분간 `section` 을 생략한다) | 2b (지금)                 |
| `highlightCity` | `{ slug, city }`                                               | 4단계 (지금)              |

- 답변 텍스트가 끝난 뒤, `done` 앞에 **한 번만** 보낸다. 순서는 `text_delta... → action → done` 이다.
- 에러·취소로 끝나는 요청에서는 보내지 않는다.
- `retract` 된 턴도 action 을 보내지 않는다. 순서는 `text_delta... → retract → done` 이다.
- `slug` 는 서버가 `/api/artists` 로 만든 enum 으로 검증한 값만 보낸다. 한 답변에서 여러 번 호출되려 하면 마지막 유효한 것 하나만 보낸다.
- 액션 도구 호출은 `tool_status` 로 보내지 않는다. 프런트 사전에 `tool.focusArtist`, `tool.openTour` 키를 추가하지 않아도 된다.

## 서버의 `highlightCity` 규칙

- `slug` 는 enum 으로, `city` 는 **그 아티스트의 공연 도시 코드**(`cities[].code`) 안에 있을 때만 보낸다. 다른 아티스트의 도시는 보내지 않는다.
- 현재 화면이 그 아티스트의 투어 페이지(`context.view="tour"`, 같은 `slug`)일 때만 보낸다. 그 밖의 화면에서는 `openTour`·`focusArtist` 를 쓴다. 이 조건은 on-stage 가 `highlightCity` 를 지원하는 화면을 알려 주면 바뀐다 (설계 §14.6 H3).
- 한 답변에 액션은 하나다. `retract` 된 턴에서는 보내지 않는다. 순서는 `text_delta... → action → done`.

## 서버의 `openTour` 중복 필터

서버는 아래 조건을 **모두** 만족할 때만 `openTour` 를 보내지 않는다.

- `context.view` 가 `tour` 이고 `context.slug` 가 요청한 `slug` 와 같다
- `context.section` 이 `tour` 이거나 없다 (현재 섹션을 모르면 이미 투어 화면으로 본다)

현재 섹션이 `hero`, `album`, `gallery` 이면 투어 섹션으로 이동해야 하므로 `openTour` 를 **보낸다.** (앨범을 보던 사용자가 "투어 일정 보여줘" 하면 투어로 스크롤된다.) 그 밖의 중복 방어는 on-stage 가 한다.

## 의미

| 액션          | 의미                                                                                                                                                                                                                         |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `focusArtist` | 궤도 화면에서 카메라를 해당 아티스트로 옮긴다.                                                                                                                                                                               |
| `openTour`    | 해당 아티스트 페이지로 이동하고 투어 섹션이 보이게 한다. 같은 페이지 안이면 투어 섹션으로 스크롤한다. `section` 이 없으면 `tour` 로 본다. 카메라 포커스 → 페이지 이동 → 섹션 이동의 연출 순서와 자동 이동/칩 방식은 on-stage 가 결정한다. |

## on-stage 가 정해줘야 할 값

| 항목                         | 현재 상태                                                                                                         |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| 섹션 값 목록                 | **확정:** `hero`, `tour`, `album`, `gallery`. `openTour.section` 도 같은 값이며 생략하면 `tour`                   |
| 연출 순서, 자동 이동/칩 방식 | on-stage 가 결정한다. 에이전트는 `openTour` 하나만 보낸다                                                         |
| `highlightCity`              | 에이전트는 `tour/<slug>`에서만 보낸다. 다른 화면에서 쓸지·연출은 on-stage 가 정해 알려 준다 (설계 §14.6 H3)       |

## on-stage 가 해야 할 일

1. **알 수 없는 액션은 무시한다.** `type` 이 모르는 값이면 실행하지 않고 오류도 보여주지 않는다. 답변은 그대로 표시한다.
2. **실행 전에 `slug` 를 다시 검증한다.** `/api/artists` 응답의 `slug` 목록에 없으면 실행하지 않는다 (서버 검증을 신뢰하지 않는다).
3. **실행이 실패하거나 무시돼도 답변은 항상 표시한다.**
4. **모르는 필드는 무시한다.** `openTour.section` 은 없어도(`undefined`) 정상이며, 있으면 위 4개 값 중 하나다.
5. **요청마다 `context { view, slug?, section? }` 를 보낸다.** 안 보내면 에이전트는 현재 화면을 "알 수 없음"으로 보고 `focusArtist` 를 보내지 않을 수 있다. 아티스트 페이지에서는 사용자가 보고 있는 섹션을 감지해 `section` 으로 보낸다.
6. **같은 페이지에서 `openTour` 를 받으면 투어 섹션으로 스크롤한다.**
7. **계약 테스트:** 이 저장소의 `fixtures/guide_events_sample.json` 을 복사해 zod 스키마로 검증한다 (설계 §8.1). `requests` 키에 `section` 이 있는 요청 샘플이, `success_open_tour_section` 키에 `openTour.section` 이 있는 이벤트 샘플이 들어 있다.
